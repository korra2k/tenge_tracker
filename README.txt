TENGE TRACKER
=============

Личный финансовый трекер для учёта доходов и расходов, планирования бюджетов
и накоплений. Интерфейс доступен на русском, казахском и английском языках.


ВОЗМОЖНОСТИ
-----------

Публичная часть:
- Главная страница с разделами «Возможности» и «О проекте».
- Регистрация и вход по электронной почте и паролю.
- Подтверждение электронной почты и сброс пароля.
- Пятишаговый онбординг: язык, валюта, первый счёт и шаблон категорий.

Личный кабинет:
- Обзор баланса, доходов, расходов и недавних операций.
- Операции: добавление, редактирование, удаление, поиск и фильтры.
- Счета: наличные, карты, электронные кошельки и накопления.
- Бюджеты по категориям и целевые накопления.
- Отчёты по дням, неделям, месяцам и годам; экспорт операций в CSV,
  совместимый с Excel.
- Пользовательские категории и настройки.
- Профиль пользователя с редактированием имени, телефона и ссылки на фото.
- Выход из аккаунта.

Администрирование:
- Отдельный пункт «Администрирование», доступный только администратору.
- Просмотр пользователей, статистики и журнала действий.
- Изменение статуса пользователя и назначенного тарифа.
- Управление глобальными категориями и записями тарифов.


ТЕХНОЛОГИИ И СТРУКТУРА
----------------------

Проект — клиентское приложение без сборщика и backend-сервера. Firebase JS SDK
подключается как ES-модули с официального CDN.

- index.html              HTML-структура публичной страницы и кабинета.
- styles.css              Стили и адаптивная компоновка.
- app.js                  Навигация, состояние приложения, формы и обработчики.
- workspace.js            Шаблоны экранов финансовых разделов.
- translations.js         Переводы общей части интерфейса.
- module-translations.js  Переводы финансовых и административных экранов.
- firebase.js             Firebase Authentication и Firestore.
- firestore.rules         Правила доступа Firestore.
- firebase.json           Конфигурация Firebase CLI для публикации правил.
- .firebaserc             Алиас проекта Firebase.
- scripts/seed-demo-accounts.mjs Создание 25 демонстрационных аккаунтов в Emulator.


ЛОКАЛЬНЫЙ ЗАПУСК
----------------

Не открывайте index.html напрямую через file://: браузер может блокировать
ES-модули и Firebase. Запустите любой статический HTTP-сервер из папки проекта.
Например, если установлен Python:

    python -m http.server 8000

Затем откройте:

    http://localhost:8000/index.html

Для использования Firebase домен localhost должен быть разрешён в настройках
Authentication проекта. Для развёртывания приложения используйте статический
хостинг с HTTPS и добавьте его домен в Firebase Authentication.

Демо-аккаунты создаются только в Firebase Emulator. Установите зависимости:

    npm install

В первом терминале запустите Auth и Firestore эмуляторы:

    npm run emulators

Во втором терминале из папки проекта заполните их тестовыми пользователями:

    npm run seed:demo

Откройте локальное приложение в режиме Emulator:

    http://localhost:8000/index.html?emulator=1

Войдите одним из адресов demo01@tenge-tracker.test —
demo25@tenge-tracker.test с общим паролем 12345678. Адреса и пароль существуют
только в Emulator. Скрипт завершится с ошибкой, если переменные окружения
Auth/Firestore Emulator указывают не на localhost. Если переменные не заданы,
скрипт использует стандартные локальные порты 9099 и 8080.


НАСТРОЙКА FIREBASE
------------------

Приложение настроено на Firebase-проект tenge-tracker. Веб-конфигурация
Firebase находится в firebase.js. Firebase Web API key является частью
клиентской конфигурации; безопасность пользовательских данных обеспечивают
правила Firestore, а не сокрытие этого ключа.

Перед проверкой приложения:

1. В Firebase Console откройте Authentication → Sign-in method и включите
   Email/Password.
2. Создайте базу данных Firestore.
3. Убедитесь, что в Firebase Authentication разрешён используемый домен:
   localhost для локального теста или домен опубликованного сайта.
4. Войдите в Firebase CLI под аккаунтом с доступом к проекту.
5. Из папки проекта опубликуйте правила:

       npx firebase-tools login
       npx firebase-tools deploy --only firestore:rules

Данные профиля хранятся в users/{uid}; финансовые данные пользователя —
в подколлекциях users/{uid}/accounts, transactions, budgets, goals и categories.
Глобальные категории, тарифы и журнал администратора хранятся отдельно.

Не публикуйте приватные ключи service account и не добавляйте их в клиентское
приложение. Для текущей клиентской интеграции они не требуются.


АДМИНИСТРАТОР
-------------

Отдельная ссылка «Администрирование» показывается после определения прав
администратора. Сейчас приложение распознаёт:

- аккаунт admin123@gmail.com независимо от подтверждения электронной почты;
- пользователя с Firebase custom claim admin: true.

Правила Firestore также проверяют права на стороне Firebase. Доступ к списку
всех документов users разрешён только администратору. Не выдавайте обычным
пользователям custom claim администратора. Поле role в профиле само по себе
не является достаточным подтверждением права.

Внимание: выдача доступа по неподтверждённому email небезопасна. До того, как
владелец адреса зарегистрируется, другой человек может создать Firebase
аккаунт с этим адресом и получить административный доступ. Для публичного
развёртывания предпочтительно убрать вход по email-списку и использовать
только custom claim, назначаемый доверенным сервером.

Панель позволяет просматривать пользователей, менять их статус и значение
тарифа, управлять глобальными категориями и записями тарифов, а также смотреть
статистику и журнал действий.


ДЕМОНСТРАЦИОННЫЕ ДАННЫЕ
----------------------

Если новый пользователь с адресом nurali@gmail.com проходит онбординг,
приложение один раз создаёт для него демонстрационные счета, операции,
бюджеты, цель накоплений и категории. Данные используют выбранную валюту и
сохраняются в Firestore этого аккаунта. Флаг demoDataSeeded предотвращает
повторное заполнение при последующих входах.

Это поведение предназначено для демонстрационного аккаунта. Не используйте
его для реальных финансовых данных. Для срабатывания автоматического заполнения
аккаунт должен завершить онбординг после добавления этой функции.

Отдельный локальный сценарий с 25 пользователями описан выше; он работает
только в Firebase Emulator и не создаёт реальные аккаунты в проекте.


ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ
--------------------

- CSV-экспорт доступен; интеграции с банками нет.
- Конвертация валют по внешнему курсу не подключена.
- Периодичность операций пока сохраняется как свойство, но автоматический
  запуск повторяющихся операций по расписанию не настроен.
- Записи тарифов в админ-панели не подключены к платежному провайдеру,
  автоматическому продлению подписок или полноценной системе биллинга.
- Уведомления описаны в настройках, но отправка push/email-уведомлений
  и серверное планирование не настроены.
- Для перечисленных серверных функций потребуется отдельный backend,
  Cloud Functions или другой доверенный серверный компонент.
